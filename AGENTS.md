# Shion Public Repository Re-Entry Instructions

Status: public-repository instruction layer, updated 2026-08-16.

This GitHub repository is **not** the private live Shion runtime. Do not treat a public file, remembered summary, or old output path as authority for the present local coordinate.

## If you are reading only this GitHub repository

Read in this order:

1. `README.md`
2. `CURRENTNESS_AND_EVIDENCE.md`
3. `REPOSITORY_CURRENTNESS_AUDIT.md`
4. `CODE_STATUS.md`
5. `MAP.md` when you need the public architecture map
6. historical/conceptual files only when they answer the current question

Repository-only analysis may describe public code and design history. It must not claim that a service, daemon, worker, route, endpoint, or model is currently active without a fresh authorized readback.

## If you are inside an authorized local Shion workspace

The local workspace's **current** entry instructions and current-state/readback files outrank this public repository for claims that may have changed.

Use this rule:

```text
public history / durable memory -> navigation
current authorized file or fresh readback -> present-state authority
```

Do not copy a live selected route, current worker state, current repair candidate, or in-flight coordinate into this public file as durable truth.

## Evidence discipline

Keep these separate:

- **observation** — what a file, tool, human, AI, or runtime directly returned
- **interpretation** — what the observation may mean
- **hypothesis** — a claim still needing discrimination/testing
- **execution** — an action that changed a file, process, or external system

A coherent story is not proof. A successful execution is not validation of the theory around it.

One bounded result should update only the claim it directly touches.

## Peer-AI relation

Different AIs and tools may observe different boundaries. Preserve source, observation time, uncertainty, and the returned difference. Do not force consensus merely to make the system look coherent.

Ask Binoche only when the missing observation, permission, or direction is genuinely unavailable to the current bodies/tools. Do not make him a routine relay between agents.

## Role boundary

- Shion/public repository: history, patterns, public code, and reading contracts
- authorized live Shion runtime: current state and present operational readback
- Luvit/Codex or other implementation agents: code/log/test verification within their accessible boundary
- Rua or other cloud peers: outside camera/interpretation with source labels, not current-local authority
- Binoche: observer/conductor and source of first-person or permission-gated information when needed

## Execution boundary

Do not start all daemons, call old localhost endpoints, publish, upload, or mutate external systems simply because an older document describes such a path.

Before irreversible or public action:

```text
inspect current state
→ verify permission / credentials / environment
→ one bounded action
→ readback
→ receipt
→ stop or reassess
```

Thought, interpretation, and historical exploration can remain open. Present-state and irreversible-action claims require current evidence.
